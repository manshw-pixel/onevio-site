One path, every project

From signed deal to live customer

Onboarding and expansion projects move through the same stages, so leads see every customer's progress at a glance.

  1. 1Handover
  2. 2Queued
  3. 3Planning
  4. 4In progress
  5. 5CSM review
  6. 6Live

The first project on an account is its onboarding; any later project on the same account is an expansion. A project can be put on hold from any open stage and resumes where it stopped, and an implementation lead can cancel one. Either way, its stage history is kept.

Handover

A checklist sales can't skip

Your team defines a complete handover. Required items must be filled before the project joins the queue.

  • Custom checklist with required fields
  • Start onboarding from a won opportunity
  • Projects can also arrive from your sales system feed

The checklist is yours to shape: tick boxes for things like a signed order form, and text fields for details such as the customer's admin contact or a go-live target date. Mark the items that matter as required. Until every required item is filled, the project stays in Handover and OneVio names the items still missing, so the gap is fixed before anyone starts work rather than discovered in week three.

Plan & deliver

Plans, tasks and hours in one place

Leads assign the project and start from a saved plan template. Implementers work the tasks and log time.

  • Reusable plan templates
  • Hours logged per task
  • Workload view of active projects and hours per person
  • On hold or cancelled, with history kept

A queued project moves to Planning once a lead assigns an implementer, and to In progress once the plan has at least one task. Implementers log hours against each task as they go. When every task is done, they send the project to the CSM for review. The workload view shows each person's active projects and hours, so a lead can see who has room before assigning the next customer.

Sign-off

CSM sign-off before go-live

The account's CSM reviews the project and sends it back with a note or signs it off. Once every task is signed off, the project goes live and the handover date is recorded on the account.

  • Send back with a note, or sign off
  • "Impl → CSM" handover date on the account
  • Separate implementation roles with read-only account access

The CSM signs off each task. Returning one sends the project back to In progress with the note attached, and tasks already signed stay signed. Once every task is signed off, the project goes Live and the account shows the date implementation handed it to the CSM.

After go-live, nothing moves to another tool. The same account feeds the customer health score, its renewal, license deployment, NRR and GRR reporting and invoices. Want to see what retention looks like today? Try the free NRR calculator.

FAQ

Onboarding questions

Can we run more than one project for the same customer?

Yes. An account can have several projects at once, such as an onboarding and a later expansion.

Who can see the implementation work?

Implementation leads and implementers have their own roles: the Implementation board plus read-only account records.

Can a project start before the handover checklist is complete?

No. A project stays in Handover until every required checklist item is filled, and only then can it move to the queue.

What happens after go-live?

The account carries on in OneVio: health scores, renewals, QBRs and invoicing all use the same record.
